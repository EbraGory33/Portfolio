## Why I Built This

Travel planning usually involves jumping between multiple websites to collect information. I wanted to build a centralized experience where users could browse destinations and interact with travel information inside a single application.

This project was developed during the Per Scholas Software Engineering program and became one of my first complete full-stack applications using the MERN stack.

Along the way I practiced:

- Designing a REST API
- Building reusable React components
- Managing application state
- Connecting a frontend to a backend
- Working with MongoDB
- Deploying a complete web application

## Architecture

The application follows a traditional MERN architecture.

```
React Frontend
        │
 REST API (Express)
        │
 Business Logic
        │
 MongoDB Database
```

The frontend is responsible for rendering pages and interacting with the backend through API requests.

The backend exposes REST endpoints responsible for handling business logic and communicating with MongoDB.

This separation allowed the frontend and backend to evolve independently during development.

## Frontend

The frontend was built with React and focuses on creating a responsive user experience.

Some of the UI goals included:

- Clean navigation
- Responsive layouts
- Reusable components
- Consistent styling
- Fast page interactions

Rather than placing all UI inside large page files, components were broken into smaller reusable pieces to improve maintainability.

---

## Backend

The backend uses Express to expose REST endpoints consumed by the React frontend.

Responsibilities include:

- Processing requests
- CRUD operations
- Database communication
- Returning structured JSON responses

Keeping API logic separate from presentation made the project easier to extend and debug.

---

## Challenges

One of the biggest lessons during development was understanding how every layer communicates together.

Frontend state, API requests, routing, and database operations all have to remain synchronized.

Building the project also reinforced:

- API design
- Request/response flow
- Component organization
- Database modeling
- Debugging across multiple layers

---

## What I Learned

This project helped me transition from building isolated frontend interfaces to developing complete full-stack applications.

Some of the biggest takeaways were:

- Structure matters more than size.
- Reusable components dramatically improve maintainability.
- Designing APIs before building UI reduces unnecessary refactoring.
- Separating concerns makes applications easier to extend.

The project also gave me practical experience working across the full request lifecycle—from a user interaction in React all the way to database operations in MongoDB.
